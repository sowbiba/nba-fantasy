# L3a — Elo, correction blessures, écart de force, affichage connecté — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un Elo maison des 30 équipes (corrigé des blessés), validé sur 2025-26, qui alimente les chances de victoire et l'écart attendu de chaque match, un facteur « écart de force » optionnel dans les projections SR (activé seulement s'il gagne au backtest), et l'affichage connecté (colonne Force du Classement, chances de victoire sur Ce soir).

**Architecture:** `engine/stats/elo.py` pur (notes, prédictions, correction blessures) ; `engine/stats/blowout.py` pur (calibration minutes ↔ écart, facteur) ; `daily_sync` écrit `team_elo` et `game_predictions` ; `decide` reçoit l'écart attendu par match via `GameContext.expected_margin` et applique le facteur si `BLOWOUT_ENABLED` ; le backtest L2 gagne une option `blowout` ; un job de rapport Elo en lecture seule choisit les paramètres. Front : lecture serveur via `ownerDb()`.

**Tech Stack:** Python 3.14 (pytest), Postgres Supabase (RLS), Next.js 16 (Node 22, vitest).

**Spec:** `docs/superpowers/specs/2026-09-28-l3a-elo-design.md` ; `docs/strategie-ttfl.md` S5 ; spec de base `docs/superpowers/specs/2026-09-26-moteur-sr-po-design.md` §7 (règle d'activation).

## Global Constraints

- **Pas de fuite du futur** : une prédiction pour un match du jour D n'utilise que les matchs terminés avant D ; la calibration du facteur d'écart dans le backtest n'utilise que les logs avant D.
- Elo et prédictions = données du **mode connecté** : aucune lecture publique (RLS sans politique anon), lecture front via `ownerDb()` seulement, ajoutées au test anti-fuite `web/src/lib/no-private-leak.test.ts`.
- `BLOWOUT_ENABLED = False` par défaut ; activation seulement si le backtest le justifie dans les deux modes de blessures et avec l'accord de l'utilisateur.
- Python : `./venv/bin/python -m pytest -q` ; SQL : `TEST_DATABASE_URL=postgresql://postgres:pg@localhost:55432/postgres` ; front : Node 22 (`export PATH=/home/isow/.nvm/versions/node/v22.23.3/bin:$PATH`), docs Next 16 dans `web/node_modules/next/dist/docs/`.
- Jamais d'écriture en prod, de job lancé contre la prod, de `db push`, de déploiement ni de push hors de la tâche 7 (feu vert de l'utilisateur). Le rapport Elo et le backtest (lecture seule) tournent à la tâche 7.

## Review Focus

1. **Ordre chronologique et matchs du même jour** : les notes d'avant-match d'un jour D ne doivent contenir aucun résultat de D (deux matchs d'une même équipe impossibles le même jour, mais l'ordre des matchs d'un soir ne doit rien changer aux prédictions de ce soir). Test tâche 2.
2. **Équipes sans match récent / début de saison** : 1500 ou note reportée avec retour vers la moyenne ; aucune division par zéro dans la part des absents d'une équipe sans logs. Test tâche 2.
3. **Match reporté / sans score** : ignoré par l'Elo, jamais compté comme une défaite. Test tâche 2.
4. **Facteur d'écart sans effet quand désactivé** : avec `BLOWOUT_ENABLED = False`, projections et recommandations strictement identiques à aujourd'hui. Test tâche 4.
5. **Fuite de l'Elo en mode public** : aucune page publique ne lit `team_elo` / `game_predictions`. Test tâche 6.

### Task 2: `engine/stats/elo.py` — notes, prédictions, correction blessures

**Files:** Create `engine/stats/elo.py`, `tests/stats/test_elo.py`

**Interfaces:**

```python
@dataclass(frozen=True)
class EloParams:
    k: float = 20.0
    home_advantage: float = 70.0
    carryover: float = 0.75          # R ← carryover·R + (1−carryover)·MEAN à chaque nouvelle saison
    mean: float = 1505.0
    elo_per_share: float = 0.0        # correction blessures (0 = désactivée tant que non calibrée)
    points_per_elo: float = 1 / 28

def win_prob(home: float, away: float, p: EloParams) -> float
def expected_margin(home: float, away: float, p: EloParams) -> float
def mov_multiplier(margin: int, winner_elo_diff: float) -> float   # ((|m|+3)^0.8)/(7.5+0.006·diff)
def ratings_before(games: list[dict], before: date, p: EloParams) -> dict[str, float]
    """Notes de toutes les équipes vues, après tous les matchs terminés (status 'final', scores
    non nuls, game_type ∈ {regular, cup_final, playoffs}) de date < before, en ordre
    (date, id) ; retour vers la moyenne au changement de saison."""
def team_shares(logs: list[GameLog], team: str, before: date, window: int = 15) -> dict[int, float]
    """Part de chaque joueur dans la production de l'équipe (minutes × TTFL/min) sur ses
    `window` derniers matchs avant `before` ; somme = 1 ; {} si aucun log."""
def adjusted(rating: float, absent_share: float, p: EloParams) -> float   # rating − elo_per_share·share
@dataclass(frozen=True)
class GamePrediction:
    game_id: str; home_rating: float; away_rating: float; home_win_prob: float; expected_margin: float
def predict(game: dict, ratings: dict[str, float], absent_share: dict[str, float], p: EloParams) -> GamePrediction
```

- [ ] Tests : probabilité 0,5 à notes égales sans avantage ; avantage du terrain ; mise à jour à somme nulle ; multiplicateur d'écart croissant avec l'écart ; `ratings_before(D)` ignore les matchs de D et après, les matchs sans score et la présaison ; retour vers la moyenne au changement de saison ; `team_shares` somme à 1 et `{}` sans logs ; `adjusted` baisse la note ; `predict` cohérent (écart attendu = différence corrigée × points_per_elo). → implémenter → PASS → commit `feat(engine): Elo maison, prédictions de match et correction blessures`.
